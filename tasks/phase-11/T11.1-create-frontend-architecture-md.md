Create `frontend/ARCHITECTURE.md`:

```markdown
# AIPROXY Frontend Architecture

## Overview

AIPROXY frontend is a **thin UI client** that communicates with a Go backend. The frontend contains NO business logic, NO persistence, and NO provider execution.

## Core Principles

1. **Backend is authoritative** - All data comes from backend API
2. **Frontend renders** - UI, state, and user interaction only
3. **No persistence** - No SQLite, no IndexedDB, no filesystem
4. **No provider logic** - Backend handles all AI provider communication

## Architecture Diagram

\`\`\`
Browser
    ↓
Next.js Frontend (thin)
    ├── UI Components
    ├── State Management (Zustand)
    └── API Clients → Backend
                            ↓
                    Go Backend
                            ↓
                    PostgreSQL / Providers
\`\`\`

## Allowed Patterns

### API Communication

\`\`\`typescript
// Use API clients
import { getProviders } from '@/lib/providers-api';

const providers = await getProviders();
\`\`\`

### Authenticated Requests

\`\`\`typescript
// Use authFetch
import { authFetch } from '@/lib/http';

const data = await authFetch('/api/endpoint');
\`\`\`

### Streaming

\`\`\`typescript
// Use SSE consumer
import { consumeStream } from '@/sse';

for await (const chunk of consumeStream(response)) {
  render(chunk);
}
\`\`\`

## Forbidden Patterns

### SQLite / Persistence

\`\`\`typescript
// ❌ FORBIDDEN
import db from 'better-sqlite3';
import { getSettings } from '@/lib/localDb';
import dataDir from '@/lib/dataDir';
\`\`\`

### Filesystem Access

\`\`\`typescript
// ❌ FORBIDDEN in client code
import fs from 'fs/promises';
\`\`\`

### Business Logic

\`\`\`typescript
// ❌ FORBIDDEN - Backend handles this
function calculatePricing(tokens: number) { ... }
function resolveProvider(model: string) { ... }
\`\`\`

### Provider Execution

\`\`\`typescript
// ❌ FORBIDDEN - Backend handles providers
import { executeClaude } from '@/lib/provider-executor';
\`\`\`

## New Feature Checklist

When adding a new feature:

1. [ ] Does data come from backend?
2. [ ] Is there an API client?
3. [ ] No persistence in frontend?
4. [ ] No provider-specific logic?
5. [ ] Uses `authFetch` for authenticated requests?

## Module Guidelines

| Module Type | Allowed | Notes |
|-------------|---------|-------|
| UI Components | ✅ | React components, styling |
| State Management | ✅ | Zustand, transient state |
| API Clients | ✅ | HTTP requests to backend |
| SSE Consumer | ✅ | Render backend streams |
| SQLite | ❌ | BANNED |
| Filesystem | ❌ | BANNED in client code |
| Provider Logic | ❌ | Backend only |

## Enforcement

3. Pre-commit hooks (T11.5)
```
