## Execution

### Step 1: Explore Backend Stream Implementation

```bash
cd /home/ubuntu/ai_proxy/backend
ls -la internal/stream/
ls -la internal/translator/
```

### Step 2: Identify Stream Format

Find the normalized chunk format:

```bash
rg -n "event|chunk|delta|done|error" internal/stream/
```

### Step 3: Document Event Types

Identify all event types:
- `delta` - Content chunk
- `done` - Stream complete
- `error` - Error occurred
- `retry` - Retry indicator (optional)
- `usage` - Token usage (optional)

### Step 4: Document JSON Schema

For each event type, document the JSON schema:

```json
// delta event
{
  "type": "delta",
  "content": "string"
}

// done event
{
  "type": "done"
}

// error event
{
  "type": "error",
  "message": "string",
  "code": "string?"
}
```

### Step 5: Create Stream Contract Document

Create `docs/STREAM_CONTRACT.md`:

```markdown
# Backend Stream Contract

## Overview

Backend normalizes all provider streams to a unified format.

## Event Types

### delta
Content chunk.
\`\`\`json
{ "type": "delta", "content": "..." }
\`\`\`

### done
Stream complete.
\`\`\`json
{ "type": "done" }
\`\`\`

### error
Error occurred.
\`\`\`json
{ "type": "error", "message": "...", "code": "..." }
\`\`\`

## Transport

- POST endpoints: Server-Sent Events (SSE)
- GET endpoints: EventSource

## Notes

Frontend MUST NOT parse provider-native formats.
```
