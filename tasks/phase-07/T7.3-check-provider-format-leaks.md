# T7.3 — Check Provider Format Leaks

## Task Identity

| Field | Value |
|-------|-------|

## Objective

If any provider-format leaks through backend stream (raw OpenAI/CL4ude/Gemini deltas reach frontend), file backend ticket. Do NOT patch in frontend.

## Source Documents

- `FRONTEND_MIGRATION_TASK_INDEX.md` § Phase 7
- T7.1 output: `docs/STREAM_CONTRACT.md`

## Prerequisites

- T7.2 complete

## Execution

### Step 1: Check Backend Stream Output

Review backend stream normalization:

```bash
cd /home/ubuntu/ai_proxy/backend
rg -n "openai|claude|gemini" internal/stream/
```

### Step 2: Check for Provider-Specific Fields

Look for provider-specific fields that might leak:

```bash
rg -n "finish_reason|role|provider" internal/stream/
```

### Step 3: Test Stream Output

Start backend and test:

```bash
curl -N http://localhost:1432/api/v1/chat \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"messages":[{"role":"user","content":"hi"}]}'
```

Verify output only contains normalized format.

### Step 4: Check Frontend for Provider-Specific Handling

```bash
cd /home/ubuntu/ai_proxy/frontend
rg -n "finish_reason|claude|openai|gemini" src/sse/
```

### Step 5: File Backend Ticket If Needed

If provider format leaks:

1. Document the leak
2. File ticket in backend repo
3. Do NOT add workaround in frontend

Example ticket:
```
Title: Provider format leaking through stream normalization

Description: 
When using [provider], the following fields leak through:
- finish_reason
- provider-specific field X

Expected: Only normalized delta/done/error events

Files: internal/stream/...
```
