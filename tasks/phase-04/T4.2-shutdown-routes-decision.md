## Execution

### Step 1: Identify Shutdown Routes

```bash
cd /home/ubuntu/ai_proxy/frontend
find src/app/api/shutdown -name "route.*" -type f
```

### Step 2: Read Current Implementation

```bash
cat src/app/api/shutdown/route.ts
```

### Step 3: Determine Action

Decision tree:

| Condition | Action |
|-----------|--------|
| Backend has equivalent endpoint | PROXY |
| Backend manages lifecycle independently | DELETE |
| Frontend must trigger shutdown | KEEP-AS-IS (PM sign-off) |

### Step 4: Check Backend

```bash
cd /home/ubuntu/ai_proxy/backend
rg -n "shutdown" internal/api/
```

If no equivalent, likely DELETE.

### Step 5: Execute Decision

#### If DELETE:

1. Find all consumers:
```bash
rg -n "api/shutdown" src/
```

2. Remove or update consumers

3. Delete route files:
```bash
rm -rf src/app/api/shutdown/
```

#### If PROXY:

1. Apply standard `proxyToBackend` pattern

2. Verify functionality

#### If KEEP-AS-IS:

1. Document reasoning

2. Get PM sign-off

### Step 6: Verify Build

```bash
tsc --noEmit
npm run build
```
