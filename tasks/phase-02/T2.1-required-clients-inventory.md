## Objective

Inventory required client surface: from `T0.1` shim-importer list, build a function signature catalog (every exported function from `usageDb.js` and `localDb.js` that is called somewhere).

## Execution

### Step 1: Read T0.1 Inventory

```bash
cd /home/ubuntu/ai_proxy
cat docs/migration/inventory/sqlite-importers.txt
```

### Step 2: Identify Shim Modules

List all shim modules that need replacement clients:

```bash
cd /home/ubuntu/ai_proxy/frontend

# Find usageDb exports
rg -n "export (function|const|async)" src/lib/usageDb.js

# Find localDb exports
rg -n "export (function|const|async)" src/lib/localDb.js

# Find db/ exports
rg -n "export (function|const|async)" src/lib/db/
```

### Step 3: Map Importers to Functions

For each importing file found in T0.1:

1. Identify which function is called
2. Record the function signature
3. Note the return type

### Step 4: Build Function Catalog

Create catalog at:

```
docs/migration/inventory/required-clients.md
```

Format:

```markdown
# Required Backend API Clients

## usageDb Functions

| Function | Signature | Callers | Replacement Endpoint |
|----------|-----------|---------|---------------------|
| getUsage | `() => Promise<UsageStats>` | page.tsx, api/usage | GET /api/usage |
| saveUsage | `(usage: UsageStats) => Promise<void>` | api/usage | POST /api/usage |

## localDb Functions

| Function | Signature | Callers | Replacement Endpoint |
|----------|-----------|---------|---------------------|
| ... | ... | ... | ... |

## db/ Functions

| Function | Signature | Callers | Replacement Endpoint |
|----------|-----------|---------|---------------------|
| ... | ... | ... | ... |
```

### Step 5: Verify Against Backend

Check `API_CONTRACT.md` and backend routes to confirm each function has a backend equivalent:

```bash
cd /home/ubuntu/ai_proxy/backend
rg -n "GET|POST|PUT|DELETE" internal/api/
```
